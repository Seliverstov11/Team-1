# Bakeloom — сайт магазина и CRM

Клиентская часть магазина и CRM для владельца, менеджеров и склада — один проект, одна сборка:

- **сайт** — каталог, карточка товара, корзина, оформление, профиль покупателя (вход по паролю, заказы, отслеживание);
- **CRM** — папка `crm/`, по макету Figma «🗂 CRM · Менеджер и склад»: заказы, оплата, клиенты, склад, сборка, каталог и цены.

Данные — только из backend API (ветка `feat/backend-api`, ТЗ BAKELOOM v1.0). Контракт — `backend/openapi.yaml`,
запуск и демо-входы — `backend/README.md`. Заказ с сайта сразу появляется в CRM, смена статуса видна покупателю,
приход на склад меняет остатки на сайте.

## Запуск

Нужны Node.js 20+ и backend из ветки `feat/backend-api` (Rust или Docker). Два терминала:

```bash
# 1. backend — из ветки feat/backend-api
cd backend && cp .env.example .env && cargo run      # http://localhost:8080, база data.db создаётся сама

# 2. сайт и CRM
cd frontend && npm start                             # http://localhost:5174, CRM — http://localhost:5174/crm/
```

Dev-сервер проксирует `/api/*` на backend (`vite.config.js`), поэтому коллегам в сети нужен только порт 5174.
Другой адрес backend — `BAKELOOM_API=http://host:8080 npm start`; для собранной версии на другом домене —
`VITE_API_BASE=https://api.example.kz/api npm run build`.
Сбросить данные к исходным — остановить backend, удалить `backend/data.db*`, запустить снова.

### Входы

**CRM** — `/crm/`, без входа перекидывает на `/crm/login.html`. Пароль у всех — `BOOTSTRAP_PASSWORD` из `backend/.env`
(в образце `bakeloom-demo`).

| Логин | Роль | Что видит в CRM |
|---|---|---|
| `owner` | владелец | всё: сводка, заказы, клиенты, склад, сборка, **каталог и цены** |
| `dana`, `aliya` | менеджер | сводка, заказы и оплаты, клиенты, остатки (без прихода). Каталог не правит |
| `sklad` | кладовщик | остатки, приход, сборка и выдача. **Оплат не видит** — сервер их не отдаёт |

Права проверяет сервер (403), меню по роли только убирает лишнее. Сессия истекла или пароль сменили — CRM
сама возвращает на вход. После 5 неверных паролей подряд форма входа делает паузу на 5 минут.

**Сайт** — `account.html`: регистрация по имени, телефону и паролю (от 8 символов, строчная, заглавная, цифра,
спецсимвол; индикатор надёжности, «пароли совпадают», Caps Lock). Если на этот телефон уже заказывали —
история заказов подтягивается сама. Клиенту с персональными ценами пароль выдаёт владелец
(`POST /api/clients/{id}/password`). Без входа заказ можно найти по номеру и телефону — вкладка «Найти заказ».

### CRM как программа на рабочем столе (PWA)

CRM устанавливается как приложение: значок на рабочем столе, своё окно без адресной строки.
В Chrome и Edge в CRM появляется кнопка **«Установить приложение»** (в верхней панели и на странице входа),
то же самое — значок установки в адресной строке. После установки CRM открывается со значка.

- `public/crm/manifest.webmanifest` — название BAKELOOM CRM, `display: standalone`, старт `/crm/`, цвета из `palette.toml`
  (`crm.sidebar` #353B26), ярлыки «Заказы», «Сборка», «Остатки».
- `public/crm/icons/` — значки 192 и 512 px и maskable-вариант из логотипа BAKELOOM (`public/img/logo.svg`).
- `public/crm/sw.js` — service worker на `/crm/`. Оболочку (страницы, скрипты, стили, шрифты) берёт сначала из сети,
  без сети — из кэша; `/api/*` не кэширует никогда. Поэтому новая версия подхватывается при следующем открытии,
  переустанавливать не нужно. Поменяли логику самого `sw.js` — поднять `VERSION`, старый кэш удалится сам.

Установка работает на `https://` и на `localhost`. По адресу из локальной сети (`http://192.168…:5174`) браузер
установку не предложит — это ограничение браузеров, для показа нужен https-стенд (#31).

### Доступ из локальной сети

Сервер сразу слушает локальную сеть. При запуске Vite печатает адрес для коллег в строке `Network:`,
например `http://192.168.1.15:5174` — его открывают на другом компьютере в той же сети.

Если с другого компьютера не открывается — порт закрыт файрволом. Открыть (Linux, ufw):

```bash
sudo ufw allow 5174/tcp        # dev-сервер
sudo ufw allow 4174/tcp        # npm run preview, если нужен
```

Закрыть после показа: `sudo ufw delete allow 5174/tcp`. В Windows — разрешить Node.js в брандмауэре
для частных сетей (Windows сам спросит при первом запуске).

Другие команды:

| Команда | Что делает |
|---|---|
| `npm run dev` | dev-сервер без установки зависимостей |
| `npm run build` | сборка в `dist/` (Tailwind собирается вместе с проектом, без CDN) |
| `npm run preview` | просмотр собранной версии |

`node_modules/` и `dist/` в репозиторий не попадают (`.gitignore`).

## Полный цикл заказа — как проверить

1. Сайт: положить товар в корзину, оформить (курьер по Астане — доставка 1 200 ₸, межгород — 2 500 ₸).
2. CRM под `dana`: заказ в «Новых» → «Изменить статус» → «Подтверждён». Недопустимый переход сервер
   отклоняет (409), текст причины показывается в карточке.
3. CRM под `sklad` → «Сборка и выдача»: у позиции «Не хватает» → указать количество. Заказ становится проблемным.
4. CRM под `dana`: в карточке заказа уменьшить количество или убрать позицию — проблема снимается сама.
5. `sklad`: отметить позиции → «Заказ собран» → «Передан в доставку» / «Выдан клиенту» (остаток списывается).
6. `dana`: «Отметить оплату» — полностью или предоплата; дальше «Доставлен» → «Завершён».
   Отмена оплаченного заказа — только с возвратом: CRM сначала оформляет возврат, потом отменяет.

## Стек

- HTML + **Tailwind CSS 4** через сборку (Vite + PostCSS, `@tailwindcss/postcss`)
- **Alpine.js** — весь интерактив
- Шрифты Cormorant Garamond и Montserrat подключены пакетами `@fontsource` (без Google Fonts CDN)
- Без React/Vue и без роутера: каждая страница — отдельный `.html`

| `catalog.html` | Каталог: разделы → категории, поиск, сортировка по цене, «только в наличии» |

| `checkout.html` | Оформление: форма, доставка, итог, экран «заказ принят» со ссылкой на отслеживание |
| `favorites.html` | Избранное |
| `contacts.html` | Контакты |

Фильтры каталога живут в адресе: `catalog.html?category=decor&q=свеч&sort=price-asc`,
поэтому пункты меню и поиск из шапки ведут сразу на нужную выборку.

### CRM (`/crm/`)

| Файл | Кто | Что умеет |
|---|---|---|
| `crm/login.html` | все | вход по логину и паролю |
| `crm/index.html` | владелец, менеджер | сводка из `GET /api/dashboard` за сегодня / неделю / месяц / всё время: ждут оплаты, новые, поступило оплат, ниже минимума; требуют внимания (нехватка, срочные); статусы, каналы, что закупить |
| `crm/orders.html` | владелец, менеджер | список с фильтрами по статусу и оплате (на сервере), каналу, менеджеру, срочным и проблемным; экспорт CSV; новый заказ из WhatsApp / Instagram / по телефону — клиент находится по телефону, его персональные цены считает сервер |
| `crm/order.html?id=<id>` | владелец, менеджер | смена статуса по графу (409 → текст ошибки); правка состава до сборки: количество, скидка, добавить, убрать; оплата: полностью, предоплата, снять отметку, возврат; доставка; срочность; менеджер; журнал с комментариями; накладная З-2 |
| `crm/clients.html` | владелец, менеджер | база клиентов из `/api/clients`: тип, город, каналы, сумма, выкуплено, долг, вход на сайте, свои цены |
| `crm/stock.html` | все | остаток / резерв / доступно / минимум / полка; «ниже минимума», «нет в наличии»; закупка в CSV; журнал движений; приход — владелец и кладовщик |
| `crm/picking.html` | владелец, кладовщик | очередь из `GET /api/warehouse/assembly` (срочные сверху), позиции по полкам; галочка сборки и нехватка (`short_qty`); «Собран» → «Выдан / передан» |
| `crm/catalog.html` | владелец | товары и снятые с продажи; цена, название, фасовка и карточка, описание, характеристики; новый товар с начальным остатком и полкой; снять с продажи / вернуть |

Статусы — восемь: `new → confirmed → assembled → handed_over → shipped → delivered → completed`, `cancelled` в стороне.
Самовывоз: `handed_over → completed`. Переходы проверяет сервер. Резерв — при оформлении, **списание — на `handed_over`**.

Оплата — **только вручную** (`POST /api/orders/{id}/payment`): QR Kaspi статический, система о платеже не узнаёт.
Статусы `unpaid | partial | paid | refunded`.

## Структура

```
index.html, catalog.html, …   страницы
partials/                     общие куски разметки (меню, шапка, подвал, карточка товара)
crm/*.html                    страницы CRM
src/main.js                   Alpine: хранилища и логика страниц сайта (в т.ч. профиль)
src/crm.js                    Alpine: логика CRM
src/api.js                    клиент backend API — единственное место с fetch; токен входа
src/money.js                  деньги в целых тиынах и количества в тысячных: разбор строк API без parseFloat
src/catalog.js                разделы каталога (23 категории → 8 разделов), карточки из фасовок, цена, доставка
src/orders.js                 статусы, переходы, каналы, способы получения и оплаты
src/util.js                   форматирование дат, телефона
src/password.js               требования к паролю и индикатор надёжности
palette.toml                  цветовая палитра UI-кита — единственный источник цветов
tailwind.config.js            дизайн-токены: читает палитру из palette.toml + шрифты, размеры текста, радиусы, тени
postcss.config.js             подключение Tailwind к сборке
src/input.css                 вход Tailwind: шрифты, компоненты (кнопки, поля, меню)
src/fonts.css                 @font-face для Cormorant Garamond и Montserrat
public/img/logo.svg           логотип
public/crm/                   PWA CRM: manifest.webmanifest, sw.js, значки
```

Общие куски подключаются комментарием `<!-- @include имя.html -->` — его на этапе сборки
заменяет небольшой плагин в `vite.config.js`. Шапку и меню правим в одном месте.

## Дизайн-токены

**Цвета** — только в **`palette.toml`**: у каждого цвета HEX, имя стиля в Figma и назначение.
Шрифты, размеры текста, радиусы и тени — в `tailwind.config.js` (он же читает палитру из `palette.toml`).
Значения перенесены из Figma «🌿 UI-кит · Минималистичный & Премиум» (локальные стили «Премиум/…»).
Посмотреть всё разом: **`/tokens.html`**.

Поменять цвет — исправить `hex` в `palette.toml`. На запущенном `npm run dev` сайт перекрасится сам.

```toml
[brand.dark]                       # → bg-brand-dark, text-brand-dark, border-brand-dark…
hex = "#4A5236"
figma = "Премиум/Primary/Olive"
usage = "Основной цвет: кнопки, меню, баннер"

[error.DEFAULT]                    # DEFAULT → класс без суффикса: text-error
hex = "#B4664A"
```

Правило: в разметке пишем класс по смыслу, а не цвет.

```html
<button class="bg-[#4A5236]">   <!-- нельзя -->
<button class="btn-primary">    <!-- готовый компонент -->
<p class="text-error">          <!-- токен по смыслу -->
```

| Группа | Классы |
|---|---|
| Фирменные | `brand-dark`, `brand-dark-hover`, `brand-light`, `brand-gold`, `brand-gold-hover`, `brand-gold-light`, `brand-gold-soft`, … |
| Поверхности и текст | `surface`, `surface-sand`, `ink`, `ink-muted`, `ink-placeholder`, `on-dark`, `on-dark-muted` |
| Линии и состояния | `line`, `line-strong`, `success`, `success-soft`, `error`, `error-soft`, `disabled` |
| Шрифты | `font-heading` (Cormorant Garamond), `font-body` (Montserrat) |
| Текст | `text-display`, `text-h1`…`text-h3`, `text-price`, `text-lead`, `text-body`, `text-small`, `text-button`, `text-overline` |
| Радиусы и тени | `rounded-control` / `search` / `card` / `panel` / `check`, `shadow-subtle`, `shadow-lift` |
| Компоненты | `btn-primary`, `btn-gold`, `btn-outline`, `btn-link` (+ `btn-l`, `btn-s`), `field`, `chip`, `counter`, `eyebrow`, `demo-tag` |

Исключение — SVG-иллюстрации-заглушки товаров (`partials/product-image.html`): это картинки, а не интерфейс;
уйдут, когда появятся фото (`image_url`).

## Данные

Всё — из API, в разметке товаров нет. Деньги и количества приходят строками («1880.00», «2.500»).

- **23 категории** сгруппированы в разделы (`src/catalog.js → GROUPS`): фильтр в две ступени — раздел, затем категория.
  Новая категория из API без раздела попадает в «Другое».
- **Фасовки одной карточкой** (ФТ-Т-01): товары с общим `group_id` — одна карточка с переключателем;
  цена, остаток и артикул меняются по выбранной фасовке (в сетке и на странице товара).
- **Характеристики** (ФТ-Т-04) — из `attributes`, у каждого товара свой набор: две первые — в сетке, все — на странице товара.
- **Цена одна для всех** — опт выключен (заказчик, В3 27:47), `wholesale_price` приходит `null` и не показывается.
  Вошедший покупатель с договорной ценой видит её (`personal_price`) с зачёркнутой общей. Итог заказа считает сервер.
- **Фото нет** — заглушка по разделу с подписью «фото подбираем».
- **Нет в наличии** (`available_qty = 0`) — кнопка неактивна, в корзину не добавить.
- **Деньги** считаются в целых тиынах (`src/money.js`) без float, по той же формуле, что backend.

В `localStorage` — только удобства браузера: корзина (`bakeloom.cart.v2`), избранное (`bakeloom.favorites.v2`),
сессии сайта и CRM (раздельно, `bakeloom.client.session` / `bakeloom.crm.session`), адрес доставки по умолчанию.
Сайт сообщает о просмотрах страниц (`POST /api/analytics/visit`) — для аналитики владельца, без IP.

## Переходы между страницами без мерцания

- Стили подключены `<link>` в `<head>` — страница не рисуется без CSS.
- Скрипт с `blocking="render"`: первый кадр рисуется уже после Alpine, без «пустых» состояний и `0 ₸` в шапке.
- Справочник товаров кэшируется в `sessionStorage` (`bakeloom.catalog.v2`): на следующей странице данные есть сразу,
  свежие подгружаются в фоне. Скелетон показывается только при самом первом заходе.
- Шрифты — свои `@font-face` (`src/fonts.css`) с `font-display: block`: текст не перескакивает с системного шрифта на фирменный.
- `@view-transition` (Chrome, Edge, Safari 18): страницы сменяются плавно, меню и шапка стоят на месте, анимируется только контент.
  В браузерах без поддержки — обычный переход. Уважается `prefers-reduced-motion`.
- Активный раздел подсвечивается чистым CSS по `<body data-page="…">`, поэтому виден с первого кадра;
  в каталоге и на карточке товара дополнительно подсвечивается категория. Раскрытие меню каталога запоминается на сессию.

## Что сознательно не показано

По условиям задачи на сайте нет того, что заказчик не подтверждал: бесплатной доставки
от суммы, скидок, промокодов, сроков доставки, онлайн-оплаты, опта. Пункты меню из макета
«Новинки», «Скидки», «Мастер-классы», «Доставка», блок «Персональный подбор» и полоса преимуществ убраны.

Покупатель не отменяет заказ сам — сервер разрешает отмену только сотрудникам; в профиле подсказка «через менеджера».
Разделы макета CRM «Отчёты», «Сообщения» и «Инвентаризация», управление сотрудниками и персональными ценами
в интерфейсе пока не сделаны — в API они есть.

Цены — в тенге (₸). Контакты магазина в меню и подвале — по-прежнему заглушки («Демо-контакты»).

## Ограничения

- Адаптивная вёрстка: сайт и CRM проверены без горизонтального скролла на 360, 414, 768, 1024, 1366 и 1920 px
  и на низких окнах (1366×560). Уже 1024 px меню уезжает в выдвижную панель (кнопка ☰, Esc, клик по фону);
  в CRM на телефоне таблицы заказов, остатков, клиентов, сборки и прихода заменяются списками.
- Несуществующий адрес открывает страницу `404.html` (в dev и `npm run preview`).
- Часть цветов текста в `palette.toml` затемнена относительно Figma до контраста 4.5:1 (WCAG AA) —
  исходные значения указаны в комментариях рядом.
- Логотип — вариант 1 Bakeloom для тёмного фона (`public/img/logo.svg`).
