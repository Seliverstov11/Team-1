## 1. Итог

Проверено **46 независимых API-проверок** поверх `cargo run` плюс автотесты проекта. **43 прошли, 3 не прошли:** два дефекта кода (поиск в кириллице, округление суммы) и одно безопасное расхождение с тест-кейсом (повторная отмена). Отдельно выявлено расхождение данных: в запуске 124 позиции вместо 289. Плюс уточнён один продуктовый вопрос по опту. Дефекты и вопрос заведены отдельными issue: [#36](https://github.com/Seliverstov11/Team-1/issues/36), [#37](https://github.com/Seliverstov11/Team-1/issues/37), [#38](https://github.com/Seliverstov11/Team-1/issues/38), [#39](https://github.com/Seliverstov11/Team-1/issues/39).

Заключение по PR #14 выложено на GitHub как ревью (COMMENTED, `5918277811`) с 21 дефектом из отчёта от 12.11.2026. PR к моменту публикации был закрыт без мержа, поэтому ревью — фиксация заключения, а не аппрув.

## 2. Как проверял

```bash
cd backend
~/.cargo/bin/cargo build --tests
~/.cargo/bin/cargo test
PORT=8080 DATABASE_PATH=/tmp/opencode/run.db \
  BOOTSTRAP_PASSWORD=bakeloom-demo WHOLESALE_ENABLED=true \
  ./target/debug/bakeloom-api
python3 /tmp/opencode/apitest.py   # 46 проверок через HTTP
```

Отдельно миграции применены в SQLite до `005` и до `007`, чтобы развести заявленные и фактические цифры по остаткам.

**Автотесты проекта:** 15 unit + 9 integration, все зелёные (покрывают в основном счастливый путь, поэтому добавлен независимый прогон через HTTP).

**Независимый прогон:** 43/46. Скрипт не хранится в репозитории — это QA-инструмент, а не продукт; проверки воспроизводимы по `backend/openapi.yaml`, исходные данные прогона приведены ниже.

## 3. Подтверждённые дефекты

| ID | Суть | Issue |
|---|---|---|
| BACK-01 | `GET /api/catalog/products?search=шоколад` → 0, при `?search=Шоколад` → 9. SQLite `LIKE` регистронезависим только для ASCII | [#36](https://github.com/Seliverstov11/Team-1/issues/36) |
| BACK-02 | 0,5 кг × 333,33 ₸ = `166.66` вместо `166.67`: целочисленное усечение в `line_subtotal` | [#37](https://github.com/Seliverstov11/Team-1/issues/37) |
| BACK-03 | В запуске 124 позиции вместо 289; 8 с нулевым остатком и 39 ниже минимума (по доступному 15 / 51) вместо 37 / 111. `007_seed_sample.sql` удаляет каталог `005` | [#38](https://github.com/Seliverstov11/Team-1/issues/38) |

**Вопрос:** [#39](https://github.com/Seliverstov11/Team-1/issues/39) — опт выключен по умолчанию; включать ли на демо 18.11.

### Детали BACK-02

Проверка D-02 (0,7 × 1999,99 = 1399,993 → 1399,99) проходит совпадением: усечение и корректное округление дают одинаковый результат. D-03 с 166,665 ₸ показывает расхождение в 1 тиын. Правило округления зафиксировано в тест-плане как «вверх от половины» и требует подтверждения автором бэкенда.

### Детали BACK-03

| Показатель | #23 / `005` | Запуск (`007`) |
|---|---|---|
| Позиций | 289 | 124 |
| `stock - reserved <= 0` | 37 | 15 |
| `stock - reserved < min_stock` | 111 | 51 |
| `stock == 0` | 33 | 8 |
| `stock < min_stock` | 108 | 47 |

Цифры 37 / 111 из #23 **верны для полного каталога**, но не для того, что реально поднимается командой из issue. Деньги в сиде при этом сходятся полностью: шапка = сумма строк, итог = товары + доставка, цена × количество = сумма строки, 24 заказа без позиций-сирот.

### Наблюдения, не ставшие дефектами

- Повторный перевод в `cancelled` возвращает **200 no-op** и не задваивает резерв — поведение безопасно, тест-кейс ожидал 409; в issue не заведено, так как данных не портит.
- Резерв в сиде согласован с активными заказами (0 расхождений).
- Все 24 заказа содержат позиции, все цены строк совпадают с розничной или оптовой ценой товара, опт не применяется ниже порога.
- `is_weight` и `min_order` / `order_step` в сиде — значения по умолчанию, поэтому весовые кейсы проверены на товарах, созданных через API.

## 4. Ревью PR #14

Ревью от 12.11 (21 дефект: 4 высоких, 6 средних, 11 низких) перенесено на GitHub как review PR #14 (`5918277811`, состояние COMMENTED). Источник — `docs/отчеты/12.11.26/Токубаев_Омар_отчет_о_проверке.docx` на ветке `DEV`. В тексте сохранена оговорка, что проверка шла по диффу и скриншоту, и помечено, что PR закрыт без мержа.

Ревью — это не аппрув: четыре дефекта (BUG-01, BUG-02, BUG-03, BUG-21) остаются блокирующими для показа.

## 5. Выводы

Бэкенд в целом готов к прогону: деньги, резерв/списание, статусы и варианты работают и на новых заказах, а не только на сиде. Два дефекта кода (поиск и округление) и одно расхождение данных/документации (124/289) не блокируют большинство сценариев, но должны быть закрыты до показа: поиск — основной сценарий витрины, округление — деньги, расхождение сида — доверие к тест-плану и цифрам в #23.

Рекомендация тимлиду: подтвердить правило округления и намеренность сокращения каталога, решить судьбу опта (#39), затем перепроверить K-01 и D-03 и обновить тест-план под фактический сид.
