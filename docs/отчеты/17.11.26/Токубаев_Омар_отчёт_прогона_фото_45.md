| Браузер | Chromium headless, viewport 1280×800 и 360×740 |
| Логины | `owner`, `sklad`, `dana`, пароль `bakeloom-demo` |

Почему не живой стенд: PR #48/#49/#50/#51 остаются открытыми и не влиты в `DEV`; превью Vercel приватные; настоящих ключей `PEXELS_API_KEY` / `CLOUDINARY_URL` нет; файла выбора фото из #42 в `DEV` нет. Поэтому:

- все фото в прогоне — **тестовые/сгенерированные**, а не финальные фото заказчика;
- «фото с телефона» имитировано файлом 3024×4032 JPEG (`/tmp/opencode/photo-qa-phone-photo.jpg`), не настоящим телефоном;
- заглушка Cloudinary не применяет трансформации из URL (`c_fill,g_auto,w_800,h_800`), поэтому на сайте видно исходное изображение, а не результат реальной обработки;
- пункт про 30 позиций **не проверен** — не с чем сравнивать фото и характеристики.

## 6. Дефекты

### D-01. Карточка каталога обрезает квадратное фото товара на ~12 % по высоте

- Критичность: обычный (визуальный, ФТ-Т-08 «фото не обрезано»).
- Окружение: локальный стенд из PR #48/#49/#50/#51, Chromium 1280×800, `owner`, товар `QA45-002`.
- Шаги: 1) в CRM создать товар, «Подобрать» → выбрать фото, сохранить; 2) открыть `/catalog.html?q=QA45-002`; 3) сравнить контейнер и изображение.
- Ожидаемо: фото 800×800 полностью помещается в карточке, без обрезки и полос.
- Фактически: `object-fit: cover` в контейнере `aspect-[227/200]`; box 196×173 против natural 800×800 → видно 88,1 %, обрезается 11,9 % по высоте; на 360 px ~12 %.
- Скриншот: [defect-card-crop-800.png](screenshots/defect-card-crop-800.png).
- Issue: [#53](https://github.com/Seliverstov11/Team-1/issues/53).
- Предполагаемое исправление: для карточки каталога использовать `aspect-square` (как в карточке товара) либо `object-contain` с фоном бренда, либо заранее готовить изображение под 227:200; согласовать с ФТ-Т-07/08.

Отчёт и скриншоты опубликованы в [PR #52](https://github.com/Seliverstov11/Team-1/pull/52).
